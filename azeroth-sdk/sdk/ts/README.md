# azeroth-sdk TypeScript client

A typed client for the `azsdk` daemon's JSON-RPC API. No dependencies beyond `fetch`; written for bun (the files
import each other with `.ts` extensions, and there is no build step).

```ts
import { Azeroth } from "./azeroth-sdk/sdk/ts/src/index.ts";

const az = new Azeroth("http://127.0.0.1:8780");     // the daemon's -listen address
console.log(await az.sessions());                    // [{char, status, error}]
const me = az.character("Garrick");

const s = await me.api.me.status();                  // one call per Lua API function: me.api.<namespace>.<fn>
const r = await me.api.move.to(s.position.x + 15, s.position.y, s.position.z);  // a Result: pending until it resolves
const done = await me.await(r);                      // wait for the result event
console.log(done.ok ? done.data : done.error);

await me.eval("return units.nearby(30)");            // run Lua in the character's session
for await (const ev of me.events({ types: ["chat"] })) console.log(ev.data);
```

| `Character` member | RPC method | |
|---|---|---|
| `api.<ns>.<fn>(...)` | `api.call` | the game API (`docs/api-reference.md`); actions return a `Result` |
| `eval(code)` | `script.eval` | run Lua; `{result, events?, script_errors?}` |
| `query(q)` | `events.query` | past events, nothing consumed |
| `wait(q, timeoutS)` | `events.wait` | the next matching events, or `[]` after the timeout |
| `events(q)` | `events.wait` | async generator over every matching event from now (or `q.since`) |
| `await(result, timeoutS)` | `events.wait` | the final result of a pending action |

RPC errors throw `RpcError` (with the JSON-RPC `code`). `Azeroth.call(method, params)` reaches any method directly.

`examples/smoke.ts` exercises the client against a running character:

```sh
AZSDK_URL=http://127.0.0.1:8780 bun examples/smoke.ts Garrick
```

## Generated files

`src/types.ts` (every type and event) and `src/api.ts` (`gameApi`, one function per Lua API function) are
generated by `cmd/apigen` from a live session's function registry and package `types`. Don't edit them by hand;
`src/index.ts` is hand-written. To regenerate after changing the Lua API or `types`, from the repo root:

```sh
sh bench/dev/apidoc.sh
```

It builds `azsdk-dev`, starts the GM dev character if it isn't running, runs `apigen` (which also writes
`docs/api-reference.md`) and type-checks this package with `tsc`. Lua-only functions (tasks, waiting, events,
`client.*`, `act.*`) are left out of `api.ts`.
